# gyeoL — 로테이션 소개팅 앱

결이 맞는 사람을 만나는 곳. 설치 없이 QR이나 링크로 들어와 휴대폰 번호만 입력하면 입장합니다.
색·글꼴·히어로 이미지(`assets/hero.jpg`)는 브랜드 포스터에서 가져왔습니다.

## 진행자 로그인 (마스터키)

진행자는 **마스터키 하나를 모두가 함께** 씁니다. 계정은 따로 없습니다. 마스터키는 휴대폰 번호 형태의 숫자(예: `010-1234-5678`)입니다.
- **참가자와 같은 입장 화면**의 번호 칸에 마스터키를 입력하면 진행자 화면으로 넘어갑니다. (명단에 없는 번호일 때만 마스터키인지 확인합니다.) `admin.html` 에 바로 들어가 입력해도 됩니다.
- 하이픈은 자동으로 채워지고, 서버는 숫자만 비교합니다.
- 마스터키는 `supabase/schema.sql` 의 `01000000000` 자리에 적습니다. 바꾸려면 Supabase SQL Editor에서 `update app_settings set admin_pin = '01098765432' where id = 1;`
- **예시 번호(`01012345678`)처럼 짐작하기 쉬운 번호는 쓰지 마세요.** 마스터키를 아는 사람은 누구나 진행자 화면(참가자 연락처 포함)에 들어갈 수 있습니다. 행사가 끝나면 바꾸는 것이 좋습니다.
- 공동 로그인이라 누가 무엇을 했는지는 기록되지 않습니다.

## 진행자 화면 (하단 탭 4개)

위쪽의 **날짜 드롭다운**(예: `2026-11-08 · 오늘 · 13명 · 진행 중`)에서 날짜를 고르면, 그 날짜의 데이터만 보입니다. 지난 회차도 지우지 않는 한 계속 저장되어 언제든 다시 볼 수 있습니다.

| 탭 | 하는 일 |
|---|---|
| **최종 선택** | 날짜별 "매칭 결과 공개하기" 스위치, 참가자별 제출 현황, 못 찾은 입력(`?`) 확인, 선택 수동 조정, 매칭된 쌍 |
| **참가자** | 명단·통계(남녀 수, 제출 수), 한 줄 목록(번호·이름·성별·연락처, 펼치면 상세), 번호 수정·삭제, 참가자 CSV, 날짜 데이터 초기화 |
| **참가자 추가** | 구글 시트에서 한 번에 가져오기, 한 명씩 직접 등록·수정, 참가자 입장 QR |
| **설문 결과** | 문항별 통계, 홍보 동의 후기, 설문 CSV |

- **날짜 형식**: 모든 날짜는 `2026-11-08` 한 가지 형식으로 저장하고 화면에도 그대로 보여줍니다. 날짜 드롭다운에는 **참가자가 있는 날짜만** 나오고, 아직 없는 날짜는 등록 폼의 "＋ 새 날짜 추가"에서 달력으로 골라 만듭니다. 연도가 들어 있어서 해마다 같은 날짜가 겹쳐도 지난 회차 데이터가 섞이지 않습니다.
- **참가자 등록은 두 가지 방법을 함께 쓸 수 있습니다.** ① 구글 시트에서 한 번에 가져오기(시트를 CSV로 내려받아 올리거나 복사해 붙여넣기), ② 한 명씩 직접 등록. 어느 쪽이든 고른 날짜의 참가자로 한곳에 합쳐지고, 가져온 사람도 날짜 드롭다운에 `2026-11-08` 형식으로 나옵니다. **시트를 먼저 가져오고 나머지를 직접 등록하면** 번호가 겹치지 않습니다. 번호는 시트의 "현장 번호 부여" 값을 쓰고, 비어 있으면 빈 번호부터 자동 배정됩니다. **연락처는 하이픈 없이 숫자만** 저장됩니다.
- **참가자 추가·수정**: 연락처는 그 사람을 구분하는 값이라 바꿀 수 없고, 바꾸려면 삭제 후 새로 추가하세요.
- **최종 선택 조정**: 서로 선택한 경우는 붉은 숫자, 명단에서 정확히 찾지 못한 입력은 `?`로 표시됩니다. 줄을 펼치면 1~3순위를 직접 맞추거나 바꿀 수 있고(제출하지 않은 사람도, 결과 공개 후에도 가능), 조정하면 참가자 결과도 몇 초 안에 바뀝니다.
- 참가자가 번호·이름을 **정확히 맞게 적지 않아도 제출은 됩니다.** 못 찾은 입력은 진행자가 맞추기 전까지 매칭에 반영되지 않으니, 결과 공개 전에 "확인 필요 0건"인지 확인하세요.

## 회차

- 데이터는 **날짜(회차)별로 따로** 관리됩니다. 번호, 선택, 매칭, 설문, 결과 공개가 모두 그 날짜 안에서만 움직입니다.
- 진행자 화면은 위쪽 날짜 드롭다운에서 고른 **한 날짜만** 보여줍니다.
- 두 회차에 모두 있는 휴대폰 번호는 로그인할 때 **참석할 회차를 고르게** 합니다. 한 회차에만 있으면 바로 들어갑니다.

## 참가자 화면 (하단 탭 4개)

| 탭 | 쓰임새 |
|---|---|
| **내 프로필** | 상대에게 나를 소개하는 카드. 이름·나이·대학교·학과·MBTI·HOBBY, 그리고 `여성 1번`처럼 성별+번호가 크게 보입니다. |
| **대화 카드** | 대화가 막힐 때 쓰는 질문 카드. 덱의 맨 위 카드를 누르면 펼쳐지고, 다 쓰면 자동으로 다시 채워집니다. |
| **메모장** | 이성 번호(1~9)별 기억용 메모와 ♥ 끌림 표시. 나만 볼 수 있고, 상대 정보와 연결되지 않습니다. |
| **최종 선택** | 마음에 든 이성을 번호나 이름으로 최대 3명 적어 제출하고 후기 설문에 답합니다. 결과가 열리기 전까지는 언제든 제출·수정할 수 있습니다. |

## 진행자가 하는 일

진행 단계(로테이션·최종 선택 등)는 따로 없습니다. 참가자는 입장하면 모든 기능을 바로 쓰고, 최종 선택도 수시로 제출합니다.
진행자는 **회차별로 "매칭 결과 공개하기" 버튼 하나**만 누르면 됩니다.
- 공개 전에 제출 인원을 확인하세요.
- 공개하면 그 회차 참가자 화면이 자동으로 "매칭 결과"로 바뀌고, 서로 선택한 경우 상대 연락처가 열립니다. 이후에는 선택을 바꿀 수 없습니다.
- "공개 취소"를 누르면 다시 제출을 받을 수 있습니다.

## 참가자 카드

프로필 카드에는 **이름 · 나이 · 대학교·학과 · MBTI · HOBBY** 만 나옵니다. 번호는 비워 두면 자동으로 배정되고, 필요하면 참가자 목록에서 바꿀 수 있습니다.
나이는 `03년생` 형식으로 보여주며 `03`, `2003`처럼 적어도 자동으로 맞춥니다. MBTI는 대문자 4글자로 정리됩니다.

## 구글 시트에서 참가자 가져오기

1. 구글 시트에서 **파일 → 다운로드 → 쉼표로 구분된 값(.csv)**으로 내려받거나, 시트 전체를 선택(Ctrl/⌘+A)해 복사합니다.
2. 진행자 화면 **참가자 추가** 탭 → **명단 가져오기**에 파일을 올리거나 붙여넣습니다.
3. 열(연락처·이름·성별·현장 번호·나이·대학-학과·MBTI·취미·날짜)은 머리글로 자동 인식되고, 미리보기에서 바꿀 수 있습니다.
4. **가져올 날짜**를 고르고(시트에 날짜가 여러 개면 하나씩), 필요하면 "현장 번호가 있는 사람만"을 켠 뒤 **가져오기**를 누릅니다.
- **이상형·사진·입금·추가요청·친구 열은 읽지 않고 서버로도 보내지 않습니다.**
- 시트가 바뀌면 다시 가져오면 됩니다. 연락처가 같은 사람은 정보만 갱신되고 메모·선택·설문은 유지됩니다. 시트에서 빠진 사람을 지우려면 "기존 참가자 삭제"를 켜세요.
- 시트의 지저분한 값은 자동으로 정리됩니다: 전화번호 형식, `07`/`03년생`/`2003` → `03년생`, 이름 뒤에 붙은 번호(`홍길동3`), MBTI 대소문자, 취미 구분자.

## 로그인

휴대폰 번호 + **숫자 4자리 비밀번호**로 입장합니다. 명단(시트)에 있는 번호만 들어올 수 있습니다.
- **처음 입장할 때** 본인이 비밀번호를 정합니다(두 번 입력). 그 뒤로는 번호와 비밀번호로 입장합니다. 비밀번호는 해시로만 저장됩니다.
- 5번 틀리면 10분 동안 잠깁니다.
- 잊어버리면 **진행자 화면 → 참가자 → 사람 펼치기 → 비밀번호 초기화**를 누르면 다음 입장 때 다시 정합니다.
- 주의: 비밀번호는 **처음 입장한 사람**이 정합니다. 본인이 입장하기 전에 번호를 아는 다른 사람이 먼저 정할 수 있으니, 입장 링크(QR)는 행사 당일 현장에서만 공개하세요.

## 먼저 체험하기 (설정 없음)

`config.js` 를 비워 둔 채로 열면 체험 모드입니다. 이 브라우저에만 저장되고 가짜 참가자 18명이 있습니다.
체험용 번호 `010-0000-1001`(남 1번), `010-0000-2001`(여 1번), 진행자 마스터키 `010-1234-5678`.
로컬 실행: `python3 -m http.server` 후 http://localhost:8000

## 실제 행사용 설정 (약 10분, 무료)

1. https://supabase.com 에서 프로젝트 생성
2. **SQL Editor** 에 `supabase/schema.sql` 을 붙여넣고 Run. 실행 전 `01000000000` 을 진행자 마스터키로 바꾸세요.
   (이후 변경: `update app_settings set admin_pin = '01098765432' where id = 1;`)
3. **Project Settings → API** 의 URL 과 anon key 를 `config.js` 에 입력
4. GitHub Pages(Settings → Pages → main / root)로 배포
5. 입장 화면(또는 `admin.html`)에서 마스터키로 들어가 참가자를 등록하고, 입장 QR을 참가자에게 보여 주세요.

## 구글폼 연동 (신청 → 앱 실시간)

폼이 제출될 때마다 신청자 한 명이 앱의 **신청자** 탭에 바로 들어옵니다. 이후 진행자가 사진·성비를 보고 날짜(회차)에 배정합니다.
(이상형·입금·추가요청·동의 항목은 읽지도 보내지도 않고, 사진은 드라이브 링크만 보냅니다.)

1. 최신 `supabase/schema.sql` 을 Supabase SQL Editor 에서 실행합니다.
2. 20자 이상의 무작위 문자열을 정해 Supabase SQL Editor 에서 저장합니다.
   `update app_settings set form_secret = '정한-무작위-문자열' where id = 1;`
3. 구글폼의 **응답 시트**에서 확장 프로그램 → Apps Script 를 열고, `google-apps-script/form-sync.gs` 내용을 붙여넣습니다. 맨 위 `SECRET` 을 2번의 문자열과 똑같이 바꿉니다.
4. Apps Script 왼쪽의 시계 아이콘(트리거) → 트리거 추가 → 함수 `onFormSubmit`, 이벤트 소스 **스프레드시트에서**, 이벤트 유형 **양식 제출 시**. 처음에는 구글 권한 허용 창이 뜹니다.
5. 폼으로 테스트 응답을 하나 내고 진행자 화면의 **신청자** 탭에 나타나는지 확인합니다. 안 나타나면 Apps Script 의 **실행 로그**에서 오류를 봅니다.

- 폼의 날짜 질문은 **하나만 고르는 객관식**이어야 신청 날짜가 기록됩니다. 여러 날짜를 고르면 날짜 없이 들어옵니다(배정에는 문제없음).
- 같은 연락처로 다시 제출하면 정보만 갱신됩니다. 이미 날짜에 배정된 사람의 카드는 바뀌지 않습니다.
- 연동을 켜기 전에 받은 응답은 Apps Script 편집기 위쪽 함수 선택에서 **`syncAll`** 을 고르고 ▶ 실행을 한 번 누르면 한꺼번에 들어갑니다(같은 연락처는 정보만 갱신되어 여러 번 해도 안전). `syncAll` 을 5분마다 도는 시간 트리거로 걸어 두면 시트를 직접 고친 내용도 따라갑니다.
- 연동을 끄려면 `update app_settings set form_secret = '' where id = 1;`

## 결과 안내 문자 — 맥북으로 보내기 (서비스 가입 없음)

맥북의 메시지 앱이 아이폰을 통해 **일반 문자(SMS)**를 한 명씩 보내게 하는 방식입니다. 애플이 공식 지원하는 방법이 아니라 맥OS 버전에 따라 안 될 수 있으니, 행사 전에 꼭 테스트하세요.

**준비 (한 번만)**
1. 아이폰: 설정 → 메시지 → **문자 메시지 전달** → 사용할 맥북을 켭니다(맥북에 인증 코드가 뜨면 입력).
2. 맥북: **메시지 앱**을 열어 같은 Apple ID 로 로그인되어 있는지 확인합니다. 맥북과 아이폰이 모두 켜져 있고 인터넷에 연결되어 있어야 합니다.

**발송 순서 (진행자 화면 → 최종 선택 → 결과 안내 문자)**
1. 결과를 공개합니다.
2. **테스트 스크립트 받기**(내 번호 입력) → 파일을 맥북의 **스크립트 편집기**(Script Editor)로 열고 ▶ 실행 → 내 휴대폰에 문자가 오는지 확인합니다. 처음에는 "스크립트 편집기가 메시지를 제어하려 한다"는 권한 창이 뜨니 허용합니다.
3. 잘 오면 **발송 스크립트 받기** → 같은 방법으로 ▶ 실행합니다. 한 명당 5초 간격으로 나가고, 끝나면 완료/실패 건수 창이 뜹니다. 실패한 번호는 창에 나옵니다.
4. 끝나면 진행자 화면의 **발송 완료로 표시**를 눌러 중복 발송을 막고, 스크립트 파일은 **삭제**합니다(참가자 번호가 들어 있습니다).

안 될 때: 메시지 앱에서 SMS(초록색 말풍선)로 직접 한 건 보내지는지 먼저 확인하세요. 그것도 안 되면 문자 메시지 전달 설정이 문제입니다. 그래도 안 되면 아이폰으로 한 명씩 보내는 방식으로 바꿉니다.

## 결과 안내 문자 (솔라피)

결과를 공개한 뒤 진행자 화면 **최종 선택 → 결과 안내 문자**의 버튼으로 참가자 전원에게 "최종 선택 결과가 나왔어요 + 로그인 링크" 문자를 보냅니다. 결과·연락처는 문자에 담지 않고, 이미 받은 사람에게는 다시 보내지 않습니다.

1. [솔라피](https://solapi.com)에 가입하고 **발신번호를 등록·인증**합니다(문자는 사전에 인증된 번호로만 보낼 수 있습니다). 발송에 쓸 금액을 충전합니다.
2. 솔라피 개발자 설정에서 **API Key / API Secret** 을 만듭니다.
3. Supabase → **Edge Functions → Deploy a new function(Via Editor)** 에서 이름을 `send-result-sms` 로 하고 `supabase/functions/send-result-sms/index.ts` 내용을 붙여넣어 배포합니다. 함수 설정에서 **Verify JWT 는 끕니다**(이 앱의 공개 키는 JWT 가 아니라서. 대신 함수 안에서 진행자 마스터키를 확인합니다).
4. Supabase → Edge Functions → **Secrets** 에 아래 4개를 저장합니다.
   - `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`
   - `SOLAPI_SENDER` : 인증된 발신번호(숫자만)
   - `APP_URL` : 참가자 입장 주소(예: `https://gyeol.rotationdating.workers.dev`)
5. 진행자 화면에서 먼저 **테스트 1건**을 내 번호로 보내 문자가 오는지 확인한 뒤, 행사에서 **결과 안내 문자 보내기**를 누릅니다.

문안은 `supabase/functions/send-result-sms/index.ts` 의 `buildText` 와 진행자 화면(`js/admin.js` 의 `smsText`)에 있습니다. 바꿀 때는 두 곳을 같이 고치세요. 문자 서비스를 바꾸려면 `sendBatch()` 만 바꾸면 됩니다.

## 개인정보

- 브라우저는 테이블을 직접 읽지 못하고, 정해진 함수로만 접근합니다. 연락처는 `get_result()` 가 **서로 선택한 경우에만** 돌려줍니다.
- 진행자 화면의 참가자 목록에는 이름·번호·성별·연락처가 보이고, 나이·학교·MBTI·취미는 펼쳤을 때만 보입니다. 매칭된 쌍의 연락처는 참가자 본인에게만 전달됩니다. 설문은 성별만 붙어 익명으로 집계됩니다.
- 신청서의 개인정보 동의 문구가 "행사 종료 후 7일 이내 파기"라면, 행사 후 `admin.html` 의 **회차 초기화**로 앱의 데이터를 지우고 구글 시트·응답 파일도 정리하세요.
