# gyeoL — 로테이션 소개팅 앱

결이 맞는 사람을 만나는 곳. 설치 없이 QR이나 링크로 들어와 휴대폰 번호만 입력하면 입장합니다.
색·글꼴·히어로 이미지(`assets/hero.jpg`)는 브랜드 포스터에서 가져왔습니다.

## 진행자 로그인

`admin.html` 에서 **진행자 비밀번호**로 들어갑니다. 계정은 따로 없고, 비밀번호는 `supabase/schema.sql` 실행 때 정한 값(`app_settings.admin_pin`)이에요. 바꾸려면 Supabase SQL Editor에서 `update app_settings set admin_pin = '새비번' where id = 1;`
비밀번호는 서버가 매 요청마다 확인하고, 그 브라우저 탭에만 기억됩니다(탭을 닫거나 "나가기"를 누르면 해제). 참가자 화면에는 진행자 링크가 없지만 주소만 알면 접속은 되니, 비밀번호는 길게 정하세요.

## 회차

- 데이터는 **회차(예: 11/6, 11/8)별로 따로** 관리됩니다. 번호, 카드, 진행 단계, 매칭, 설문이 모두 회차 안에서만 움직입니다.
- 진행자 화면은 위쪽 회차 칩에서 고른 **한 회차만** 보여줍니다. 명단은 회차마다 한 번씩 가져옵니다.
- 두 회차에 모두 있는 휴대폰 번호는 로그인할 때 **참석할 회차를 고르게** 합니다. 한 회차에만 있으면 바로 들어갑니다.

## 진행 흐름

| 단계 | 진행자가 하는 일 | 참가자 화면 |
|---|---|---|
| **준비** | 구글 시트 응답을 **명단 가져오기**로 불러오고, 번호를 확인한다. 입장 QR을 띄운다. | 휴대폰 번호로 입장 → 내 카드 확인 |
| **로테이션** | 단계를 바꾼다 | 이성 카드 + 메모·♥ 끌림, 대화 카드 덱 |
| **최종 선택** | 단계를 바꾼다 | 최대 3명 선택 + 후기 설문 |
| **결과 발표** | 제출 인원을 확인하고 단계를 바꾼다 | 서로 선택하면 상대 연락처가 열린다 |

참가자 화면은 6초마다 단계 변화를 자동으로 반영합니다.

## 카드·명단 (구글 시트 연동)

- 카드에는 **이름 · 나이 · 대학교·학과 · MBTI · HOBBY** 만 나옵니다. 번호는 시트의 **현장 번호 부여** 열을 씁니다. 번호가 없는 사람은 같은 성별의 다음 번호가 붙고, 진행자 화면의 표에서 번호를 바꿀 수 있습니다.
- 진행자 화면 → **명단 가져오기**: 시트를 CSV로 내려받아 올리거나, 시트 전체를 복사해 붙여넣습니다. 열은 머리글로 자동 인식되고, 미리보기에서 확인·수정할 수 있습니다.
- **이상형, 사진, 입금, 추가요청, 친구 열은 읽지 않고 서버로도 보내지 않습니다.**
- 시트가 바뀌면 다시 가져오면 됩니다. 연락처가 같은 사람은 정보만 갱신되고, 메모·선택·설문은 유지됩니다. 시트에서 빠진 사람을 지우려면 "이번 명단에 없는 기존 참가자는 삭제"를 켜세요.
- 시트의 지저분한 값은 자동으로 정리됩니다: 전화번호 형식, `07` / `03년생` / `2003` → `07년생`, 이름 뒤에 붙은 번호(`홍길동3`), MBTI 대소문자, 취미 구분자.
- **가져올 회차**: 시트에 날짜(11/6, 11/8)가 섞여 있으면 회차를 골라 한 회차만 가져오세요. 같은 성별에 번호가 겹치면 가져오기가 막힙니다.

## 로그인

휴대폰 번호만 입력합니다. 명단(시트)에 있는 번호만 들어올 수 있고, 한 번 들어오면 그 브라우저에서는 계속 로그인 상태입니다. 비밀번호는 없습니다.
번호를 알면 그 사람으로 들어올 수 있다는 점은 감안하세요. 이 앱은 사전 신청자 명단과 오프라인 행사를 전제로 합니다.

## 먼저 체험하기 (설정 없음)

`config.js` 를 비워 둔 채로 열면 체험 모드입니다. 이 브라우저에만 저장되고 가짜 참가자 18명이 있습니다.
체험용 번호 `010-0000-1001`(남 1번), `010-0000-2001`(여 1번), 진행자 비밀번호 `demo`.
로컬 실행: `python3 -m http.server` 후 http://localhost:8000

## 실제 행사용 설정 (약 10분, 무료)

1. https://supabase.com 에서 프로젝트 생성
2. **SQL Editor** 에 `supabase/schema.sql` 을 붙여넣고 Run. 실행 전 `CHANGE-ME-1234` 를 진행자 비밀번호로 바꾸세요.
   (이후 변경: `update app_settings set admin_pin = '새비번' where id = 1;`)
3. **Project Settings → API** 의 URL 과 anon key 를 `config.js` 에 입력
4. GitHub Pages(Settings → Pages → main / root)로 배포
5. `admin.html` 에서 비밀번호로 들어가 명단을 가져오고, 입장 QR을 참가자에게 보여 주세요.

## 개인정보

- 브라우저는 테이블을 직접 읽지 못하고, 정해진 함수로만 접근합니다. 연락처는 `get_result()` 가 **서로 선택한 경우에만** 돌려줍니다.
- 진행자 화면의 참가자 목록에는 이름·번호·성별·연락처가 보이고, 나이·학교·MBTI·취미는 펼쳤을 때만 보입니다. 매칭된 쌍의 연락처는 참가자 본인에게만 전달됩니다. 설문은 성별만 붙어 익명으로 집계됩니다.
- 신청서의 개인정보 동의 문구가 "행사 종료 후 7일 이내 파기"라면, 행사 후 `admin.html` 의 **회차 초기화**로 앱의 데이터를 지우고 구글 시트·응답 파일도 정리하세요.

## 파일

```
index.html / admin.html   화면
js/app.js, js/admin.js    화면 로직
js/roster.js              구글 시트 → 명단 변환
js/common.js              설문 문항, 백엔드(Supabase / 체험 모드)
js/topics.js              대화 카드 질문 목록
js/vendor/qrcode.min.js   QR 생성 (MIT)
supabase/schema.sql       DB·권한·함수
```

설문 문항은 `js/common.js` 의 `SURVEY`, 대화 카드는 `js/topics.js` 만 고치면 됩니다.
