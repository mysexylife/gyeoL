# gyeoL — 로테이션 소개팅 앱

결이 맞는 사람을 만나는 곳. 설치 없이 QR이나 링크로 들어와 휴대폰 번호만 입력하면 입장합니다.
색·글꼴·히어로 이미지(`assets/hero.jpg`)는 브랜드 포스터에서 가져왔습니다.

## 진행자 로그인 (마스터키)

진행자는 **마스터키 하나를 모두가 함께** 씁니다. 계정은 따로 없습니다. 마스터키는 휴대폰 번호 형태의 숫자(예: `010-1234-5678`)입니다.
- **참가자와 같은 입장 화면**의 번호 칸에 마스터키를 입력하면 진행자 화면으로 넘어갑니다. (명단에 없는 번호일 때만 마스터키인지 확인합니다.) `admin.html` 에 바로 들어가 입력해도 됩니다.
- 하이픈은 자동으로 채워지고, 서버는 숫자만 비교합니다.
- 마스터키는 `supabase/schema.sql` 의 `01000000000` 자리에 적습니다. 바꾸려면 Supabase SQL Editor에서 `update app_settings set admin_pin = '01098765432' where id = 1;`
- **예시 번호(`01012345678`)처럼 짐작하기 쉬운 번호는 쓰지 마세요.** 마스터키를 아는 사람은 누구나 진행자 화면(참가자 연락처 포함)에 들어갈 수 있습니다. 행사가 끝나면 바꾸는 것이 좋습니다.
- 공동 로그인이라 누가 무엇을 했는지는 기록되지 않습니다.

## 진행자 화면 (하단 탭 4개)

위쪽의 **날짜 드롭다운**(예: `2026-11-08 · 오늘 · 13명 · 진행 중`)에서 날짜를 고르면, 그 날짜의 데이터만 보입니다. 지난 회차도 지우지 않는 한 계속 저장되어 언제든 다시 볼 수 있습니다.

| 탭 | 하는 일 |
|---|---|
| **최종 선택** | 날짜별 "매칭 결과 공개하기" 스위치, 참가자별 제출 현황, 못 찾은 입력(`?`) 확인, 선택 수동 조정, 매칭된 쌍 |
| **참가자** | 명단·통계(남녀 수, 제출 수), 한 줄 목록(번호·이름·성별·연락처, 펼치면 상세), 번호 수정·삭제, 참가자 CSV, 날짜 데이터 초기화 |
| **참가자 추가** | 한 명씩 직접 등록·수정(날짜 드롭다운으로 선택), 참가자 입장 QR |
| **설문 결과** | 문항별 통계, 홍보 동의 후기, 설문 CSV |

- **날짜 형식**: 모든 날짜는 `2026-11-08` 한 가지 형식으로 저장하고 화면에도 그대로 보여줍니다. 날짜 드롭다운에는 **참가자가 있는 날짜만** 나오고, 아직 없는 날짜는 등록 폼의 "＋ 새 날짜 추가"에서 달력으로 골라 만듭니다. 연도가 들어 있어서 해마다 같은 날짜가 겹쳐도 지난 회차 데이터가 섞이지 않습니다.
- **참가자는 모두 직접 등록합니다.** 날짜를 고르고 이름·성별·연락처(필수)와 번호·나이·대학-학과·MBTI·취미를 넣으면, 그 날짜의 참가자가 되어 바로 입장할 수 있습니다. 번호는 비워 두면 알아서 정해집니다. 같은 날짜·같은 성별에서 **비어 있는 가장 작은 번호**가 붙고(예: 1, 2, 4번이 있으면 3번), 빈 번호가 없으면 맨 뒤 번호가 붙습니다. 등록하면 배정된 번호를 바로 알려줍니다. **연락처는 하이픈 없이 숫자만** 입력·저장됩니다.
- **참가자 추가·수정**: 연락처는 그 사람을 구분하는 값이라 바꿀 수 없고, 바꾸려면 삭제 후 새로 추가하세요.
- **최종 선택 조정**: 서로 선택한 경우는 붉은 숫자, 명단에서 정확히 찾지 못한 입력은 `?`로 표시됩니다. 줄을 펼치면 1~3순위를 직접 맞추거나 바꿀 수 있고(제출하지 않은 사람도, 결과 공개 후에도 가능), 조정하면 참가자 결과도 몇 초 안에 바뀝니다.
- 참가자가 번호·이름을 **정확히 맞게 적지 않아도 제출은 됩니다.** 못 찾은 입력은 진행자가 맞추기 전까지 매칭에 반영되지 않으니, 결과 공개 전에 "확인 필요 0건"인지 확인하세요.

## 회차

- 데이터는 **날짜(회차)별로 따로** 관리됩니다. 번호, 선택, 매칭, 설문, 결과 공개가 모두 그 날짜 안에서만 움직입니다.
- 진행자 화면은 위쪽 날짜 드롭다운에서 고른 **한 날짜만** 보여줍니다.
- 두 회차에 모두 있는 휴대폰 번호는 로그인할 때 **참석할 회차를 고르게** 합니다. 한 회차에만 있으면 바로 들어갑니다.

## 참가자 화면 (하단 탭 4개)

| 탭 | 쓰임새 |
|---|---|
| **내 프로필** | 상대에게 나를 소개하는 카드. 이름·나이·대학교·학과·MBTI·HOBBY, 그리고 `여성 1번`처럼 성별+번호가 크게 보입니다. |
| **대화 카드** | 대화가 막힐 때 쓰는 질문 카드. 덱의 맨 위 카드를 누르면 펼쳐지고, 다 쓰면 자동으로 다시 채워집니다. |
| **메모장** | 이성 번호(1~9)별 기억용 메모와 ♥ 끌림 표시. 나만 볼 수 있고, 상대 정보와 연결되지 않습니다. |
| **최종 선택** | 마음에 든 이성을 번호나 이름으로 최대 3명 적어 제출하고 후기 설문에 답합니다. 결과가 열리기 전까지는 언제든 제출·수정할 수 있습니다. |

## 진행자가 하는 일

진행 단계(로테이션·최종 선택 등)는 따로 없습니다. 참가자는 입장하면 모든 기능을 바로 쓰고, 최종 선택도 수시로 제출합니다.
진행자는 **회차별로 "매칭 결과 공개하기" 버튼 하나**만 누르면 됩니다.
- 공개 전에 제출 인원을 확인하세요.
- 공개하면 그 회차 참가자 화면이 자동으로 "매칭 결과"로 바뀌고, 서로 선택한 경우 상대 연락처가 열립니다. 이후에는 선택을 바꿀 수 없습니다.
- "공개 취소"를 누르면 다시 제출을 받을 수 있습니다.

## 참가자 카드

프로필 카드에는 **이름 · 나이 · 대학교·학과 · MBTI · HOBBY** 만 나옵니다. 번호는 비워 두면 자동으로 배정되고, 필요하면 참가자 목록에서 바꿀 수 있습니다.
나이는 `03년생` 형식으로 보여주며 `03`, `2003`처럼 적어도 자동으로 맞춥니다. MBTI는 대문자 4글자로 정리됩니다.

## 로그인

휴대폰 번호만 입력합니다. 진행자가 등록한 번호만 들어올 수 있고, 한 번 들어오면 그 브라우저에서는 계속 로그인 상태입니다. 비밀번호는 없습니다.
번호를 알면 그 사람으로 들어올 수 있다는 점은 감안하세요. 이 앱은 사전 신청자 명단과 오프라인 행사를 전제로 합니다.

## 먼저 체험하기 (설정 없음)

`config.js` 를 비워 둔 채로 열면 체험 모드입니다. 이 브라우저에만 저장되고 가짜 참가자 18명이 있습니다.
체험용 번호 `010-0000-1001`(남 1번), `010-0000-2001`(여 1번), 진행자 마스터키 `010-1234-5678`.
로컬 실행: `python3 -m http.server` 후 http://localhost:8000

## 실제 행사용 설정 (약 10분, 무료)

1. https://supabase.com 에서 프로젝트 생성
2. **SQL Editor** 에 `supabase/schema.sql` 을 붙여넣고 Run. 실행 전 `01000000000` 을 진행자 마스터키로 바꾸세요.
   (이후 변경: `update app_settings set admin_pin = '01098765432' where id = 1;`)
3. **Project Settings → API** 의 URL 과 anon key 를 `config.js` 에 입력
4. GitHub Pages(Settings → Pages → main / root)로 배포
5. 입장 화면(또는 `admin.html`)에서 마스터키로 들어가 참가자를 등록하고, 입장 QR을 참가자에게 보여 주세요.

## 개인정보

- 브라우저는 테이블을 직접 읽지 못하고, 정해진 함수로만 접근합니다. 연락처는 `get_result()` 가 **서로 선택한 경우에만** 돌려줍니다.
- 진행자 화면의 참가자 목록에는 이름·번호·성별·연락처가 보이고, 나이·학교·MBTI·취미는 펼쳤을 때만 보입니다. 매칭된 쌍의 연락처는 참가자 본인에게만 전달됩니다. 설문은 성별만 붙어 익명으로 집계됩니다.
- 신청서의 개인정보 동의 문구가 "행사 종료 후 7일 이내 파기"라면, 행사 후 `admin.html` 의 **회차 초기화**로 앱의 데이터를 지우고 구글 시트·응답 파일도 정리하세요.

```
js/roster.js              나이·MBTI 정리 도우미
js/common.js              설문 문항, 백엔드(Supabase / 체험 모드)
js/topics.js              대화 카드 질문 목록
js/vendor/qrcode.min.js   QR 생성 (MIT)

```

설문 문항은 `js/common.js` 의 `SURVEY`, 대화 카드는 `js/topics.js` 만 고치면 됩니다.
