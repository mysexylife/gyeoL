# gyeoL 인수인계 문서

로테이션 소개팅 운영용 웹앱(참가자 앱 + 진행자 화면). 이 문서는 개발을 이어받는 사람을 위한 것입니다. 문자 관련 상세는 `docs/SMS-GUIDE.md`.

## 구성
- 정적 사이트(HTML/JS/CSS, 빌드 없음). 배포: **Cloudflare Workers 정적 파일**, 저장소 `mysexylife/gyeoL` 의 **`main` 에 push 하면 자동 배포**. 주소 `https://gyeol.rotationdating.workers.dev` (설정 `wrangler.jsonc`, 공개 제외 목록 `.assetsignore`, 응답 헤더 `_headers`). 이전 Netlify 는 크레딧 한도로 중지되어 이전함.
- 백엔드: **Supabase**(Postgres). 모든 테이블은 RLS 켜고 정책 없음 → 브라우저는 `security definer` 함수(RPC)로만 접근. `config.js` 에 프로젝트 URL 과 공개(publishable) 키.
- 화면: `index.html`+`js/app.js`(참가자), `admin.html`+`js/admin.js`(진행자), 공용 `js/common.js`(실서버 API / 체험 모드 API), `js/roster.js`(시트 가져오기), `js/macsms.js`(맥 문자 스크립트).
- DB: `supabase/schema.sql` 한 파일. **여러 번 실행해도 안전**(데이터 안 지워짐). 변경할 때마다 SQL Editor 에 통째로 다시 실행.
- 체험 모드: 주소 끝에 `?demo`. 브라우저에만 저장, 가짜 참가자(남 `010-0000-1001`~, 여 `010-0000-2001`~), 체험 마스터키 `010-1234-5678`. 로컬: `python3 -m http.server`.

## 배포 순서 (중요)
1. **서버 변경이 있으면 SQL 을 먼저 실행**하고, 그다음 화면을 push 합니다. 화면이 먼저 배포되면 새 함수가 없어 로그인 등이 막힙니다(실제로 겪음).
2. `main` 에 바로 push 하면 실사이트에 반영됩니다. 팀원은 브랜치+PR 권장(GitHub 에서 `main` 보호).
3. 배포는 Cloudflare 대시보드 → Workers & Pages → `gyeol` → Deployments 에서 확인. 반영 후 강력 새로고침(Ctrl+Shift+R).

## 저장소에 없는 것 (따로 공유)
- Supabase 프로젝트(SQL 실행, Edge Functions, Secrets), Cloudflare 프로젝트, 구글 폼 **응답 시트의 Apps Script**(확장 프로그램 → Apps Script).
- 비밀값(값은 문서에 쓰지 않음): 진행자 마스터키(`app_settings.admin_pin`), 폼 연동 비밀값(`app_settings.form_secret` = Apps Script `SECRET`), 입금 계좌 문구(`app_settings.pay_info`), (선택) 솔라피 키.
- 이 개발 대화에서 폼 연동 비밀값이 노출된 적이 있으니 **새 값으로 바꾸는 것을 권장**(SQL 과 Apps Script 두 곳을 같이).

## 기능과 합의한 결정
- **로그인**: 휴대폰 번호 + **숫자 4자리 비밀번호**. 처음 입장 때 본인이 정함(먼저 입장한 사람이 정하는 한계는 감수, QR 은 행사 당일 현장에서만 공개). 5번 틀리면 10분 잠금, 잊으면 진행자 화면에서 초기화. 해시(bcrypt) 저장, 번호 단위 하나(`accounts`). 진행자: 참가자 입장 화면 번호칸에 마스터키를 넣거나 `/admin.html`.
- **회차**: 날짜 `YYYY-MM-DD`, 같은 날 여러 타임이면 `YYYY-MM-DD HH:MM`. 타임은 완전 별개(번호·선택·매칭·결과 공개). 진행자 화면은 한 회차씩.
- **신청자 → 참가자**: 구글폼/CSV 응답은 먼저 **신청자**(회차 없음)로 들어오고, 진행자가 사진·성비를 보고 회차에 **배정**하면 번호가 붙은 **참가자**가 됨(`applicants` → `participants`). 사진은 드라이브 링크만 저장, 진행자만 봄.
- **구글폼 실시간 연동**: 응답 시트 Apps Script(`google-apps-script/form-sync.gs`)의 `onFormSubmit` 트리거가 제출 즉시 `form_submit`(비밀값 확인)을 호출. 기존 응답은 `syncAll` 한 번 실행. 트리거는 `installTrigger`. 폼 날짜 질문은 하나만 고르는 객관식.
- **최종 선택**: 이름/번호 자유 입력 3명, 진행자가 연결 못 한 입력은 맞춰 줌. 결과는 회차별 스위치로 공개(공개 전 확인 필요 0건 확인).
- **결과 화면**: "매칭 성공 / 매칭 실패" 표기, 연락처는 번호 복사 + 연락처 저장(vCard)만(전화 걸기 제거). 결과 위에 감사 인사 + 인스타(@gyeol.meet_official) 카드.
- **유료 서비스**(결과 공개 후): 득표수 확인 3,000원(숫자만, 순위·신원 없음), 연락처 전달 1명당 5,000원(매칭 안 된 상대에게, 받는 사람이 연락할지는 자유). 계좌이체 후 진행자가 입금 확인·승인. 연락처 전달에는 100자 메시지 가능(진행자가 승인 때 확인). 계좌는 `pay_info`.
- **운명의 실**: 3:3 뒤 1:1 전에 이성 1명에게 익명 메시지(60자) 1회, 보낸 뒤 취소 불가, 보내는 즉시 전달. 진행자가 스위치로 열면 참가자 화면에 팝업(6초 폴링). **매듭(서로 보냄)은 참가자에게 알리지 않음**(진행자 화면에서만 보임). 아이콘은 빨간 실 끝에 하트.
- **도착 확인**: 진행자 참가자 탭에 체크박스, 통계, 미도착만 보기.
- **디자인**: 크림 베이지 배경 + 붉은 실 포인트, 다크 모드는 어두운 갈색, 프로필 카드는 베이지 명함형, 글꼴 프리텐다드(로고만 Jost). 한때 흰 배경/핑크/클라우드 카드로 바꿨다가 되돌림(커밋 기록에 남아 있음).
- **개인정보**: 신청서 동의는 "행사 종료 후 7일 이내 파기". 행사 후 회차 초기화로 정리. 마스터키는 행사 후 변경 권장. 신청서 동의 문구에 유료 연락처 전달·익명 메시지 진행자 확인·문자 안내 보완 필요.

## 아직 검증하지 못한 것 (개발 환경에서 실서버·실기기로 못 돌림)
- 실제 Supabase 에서의 일부 SQL 동작(대부분은 사용자가 실행해 확인했으나 운명의 실·유료 승인·문자 기록 등은 전체 리허설 필요).
- **맥북 문자 발송 스크립트**(맥에서 실행 안 해 봄), 이모지 문자 처리, 솔라피 Edge Function.
- 연락처 저장(vCard) 의 실제 폰 동작, 폰에서의 스크롤 끝까지 내려가는지, 도착 확인·팝업 등 실기기 확인.
- 행사 전 **테스트 회차**(예: `2099-01-01 00:00`, 가짜 번호)로 전체 흐름을 한 번 돌리고 회차 초기화로 정리할 것을 권장.
