# 안내 문자 방법 정리 (맥북 + 아이폰)

서비스 가입 없이, **맥북의 메시지 앱이 아이폰을 통해 일반 문자(SMS)를 한 명씩 보내게 하는** 방식입니다. 애플이 공식 지원하는 방법이 아니라 맥OS 버전에 따라 안 될 수 있고, **개발 중에 맥에서 실제로 실행해 본 적이 없습니다.** 행사 전에 반드시 테스트 키트로 확인하세요.

## 문자 3종류 (진행자 화면의 [문자] 탭 → 최종 선택 탭 → 안내 문자)
| 종류 | 받는 사람 | 문안에 들어가는 것 |
|---|---|---|
| 예약 확인 | 신청자 중 아직 받지 않은 사람(하루 한 번 모아서) | `{희망날짜}` 사람마다 다름(폼에서 고른 날짜). 날짜가 없으면 그 줄이 빠짐 |
| 전날 확정 | 그 회차에 배정된 참가자 | `{일시}`(회차 날짜로 자동, 직접 입력 가능) `{장소}`(필수) `{지도}`(필수) `{도착시간}`(일시의 첫 시각 10분 전 자동) |
| 결과 안내 | 결과 공개 후 그 회차 참가자 | `{링크}` (입장 주소). 결과·연락처는 문자에 담지 않음 |

- 문안은 화면에서 고칠 수 있고 **서버(DB)에 저장**되어 어느 기기·맥북에서 열어도 같습니다(문안은 `app_settings.sms_tpl`, 회차별 일시·장소·지도는 `rounds.sms_*`). 받을 사람은 체크박스로 골라 일부만 보낼 수 있고, [발송 완료로 표시]는 선택한 사람만 기록합니다. SQL(`schema.sql`) 최신본을 먼저 실행해야 합니다. 기본 문안은 `js/admin.js` 의 `SMS_DEFAULT`.
- 종류마다 보낸 사람이 `sms_log` 에 기록되어 같은 사람에게 같은 종류를 두 번 보내지 않습니다.
- 전날 확정 기본 문안은 실제로 쓰던 양식(이모지 포함)입니다.

## 보내는 순서
1. 아이폰: 설정 → 메시지 → **문자 메시지 전달** → 맥북 켜기(맥북에 뜨는 인증 번호를 아이폰에 입력). 같은 Apple ID 필수.
2. 진행자 화면에서 종류 선택 → **테스트 스크립트 받기**(다른 사람 번호로) → 맥북 **스크립트 편집기**로 열어 ▶ 실행 → 받는 폰에 도착 확인(이모지 포함)
3. **발송 스크립트 받기** → 같은 방법으로 실행(한 명당 5초 간격)
4. **발송 완료로 표시** 클릭, 스크립트 파일 삭제(참가자 번호가 들어 있음)

## 구현 위치
- 스크립트 생성: `js/macsms.js` (`buildItems`). 모든 글자를 `character id` 번호로 적어 파일이 영문·숫자뿐. 사람별 문안 지원.
- 화면: `js/admin.js` 의 `smsPanel`, 문안 치환 `renderTpl`.
- 서버(SQL): `admin_sms_pending(p_pin, p_round, p_kind)`, `admin_sms_mark(...)`, `admin_sms_counts(...)`, 테이블 `sms_log`.
- 솔라피 자동 발송(선택): `supabase/functions/send-result-sms/index.ts`(결과 안내만, 가입·발신번호 등록·Secrets 필요, 실제 발송 미검증).

## 팀원 테스트 키트 (`tools/mac-sms-test/`)
- `sms-test.applescript`: 번호를 팝업으로 입력받아 테스트 문자 1건만 보냄(마스터키 불필요). 재생성: `node tools/mac-sms-test/make.js`
- `README.md`: 팀원용 따라 하기 안내(영어 UI 병기, 결과 보고 체크리스트).
- 진행: 팀원이 자기 맥북+아이폰으로 **진행자 번호**로 보내고, 진행자가 도착·이모지·SMS 여부를 확인해 알려줌.

## 조건과 한계
- **맥북과 아이폰이 같은 Apple ID** 여야 함 → 보내는 사람의 맥북·아이폰이 한 사람 것이어야 편함. 문자는 그 아이폰 번호로 나감. 팀원이 보내려면 팀원의 맥북+아이폰, 그리고 진행자 화면 접속(마스터키 공유) 필요.
- 맥북·아이폰이 켜져 있고 인터넷 연결 필요. 통신사가 짧은 시간 다량 발송을 막을 수 있어 5초 간격.
- 받는 사람이 아이폰이면 SMS 대신 iMessage 로 갈 수 있음. 이모지가 있으면 장문/MMS 처리로 달라질 수 있음(미확인).
- **예약 확인은 하루 한 번 모아서** 보내는 것으로 합의함(제출 즉시 자동 발송은 서비스 가입이 필요해서 제외).

## 대안 (맥북이 안 될 때 / 다른 기기)
| 방법 | 일괄 | 비고 |
|---|---|---|
| **B. 아이폰/아이패드 한 명씩 탭**(`sms:` 링크) | 아니오 | 가장 확실. **아직 안 만들었음**(A 가 안 되면 만들기로 함). 단체 문자는 번호가 서로 보여 금지 |
| 안드로이드 자동화 앱(MacroDroid/Tasker) | 예 | 앱 설정이 어려움, 가격·문자 기능 제한 미확인, 번호·문안 CSV 내려받기 **아직 안 만들었음** |
| 아이패드 | 아니오 | 애플스크립트 없음. B 방식만 가능 |
| 솔라피 등 발송 서비스 | 예 | 가입·발신번호 등록(본인 번호는 본인인증)·충전 필요. 원격 협업에 가장 적합. 코드 일부 완성(미검증) |
| 카카오 알림톡 | 예 | 비즈니스 인증(사업자등록증/고유번호증) 필요 → 사업자 없으면 불가. 결정: **문자로 진행** |

## 법·정책 메모(제가 판단할 수 없는 부분)
- 결과 안내 문자의 인스타 팔로우 한 줄은 광고성으로 볼 수 있는지 확인 필요(광고성은 사전 동의·`(광고)` 표기·야간 제한 등). 사용자가 문자에 포함하기로 함.
- 신청서 동의에 문자 안내(예약·확정·결과), 매칭 전 연락처 전달(유료), 익명 메시지 진행자 확인 문구 보완 필요.
